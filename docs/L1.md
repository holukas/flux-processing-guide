The L1 run is the final [fluxrun](scripts/fluxrun.md) run once the year is complete, with the time lags from L0 and 6 screened meteo variables as input. Its EddyPro fluxnet output, 30 min, is the input for all later steps.

The final [fluxrun](scripts/fluxrun.md) run, once the year is complete. All later steps use its results.

- **Boxes:** 6 and 7 in the [processing chain](index.md).
- **Input:** the same raw data files as the [L0 preliminary run](L0.md).
- **Meteo input:** 6 screened meteo variables, from [meteo for EddyPro](Meteo_For_EddyPro.md). See [Biomet data](Meteo_For_EddyPro.md#variables).
- **Time lags:** window size, nominal lags and constant lags from the L0 run.
- **Output:** the EddyPro fluxnet output file, 30 min, with `TIMESTAMP_END`.
- **Runs on:** a local installation, on demand.
- **Next step:** [flux post-processing chain](Flux_Post_Processing_Chain.md).

## L0 and L1 compared

The L1 run does not depend on the L0 run, but uses what L0 showed.

| | L0 | L1 |
|---|---|---|
| When | during the year | once the year is complete |
| Time lag compensation | covariance maximization, no default | covariance maximization with default |
| Time lag window | as wide as needed | as narrow as possible, e.g. 5 s for an open-path IRGA is not unusual |
| Spectral correction | Moncrieff et al. (1997), faster | Horst (1997) for open-path IRGAs; Fratini et al. (2012) for closed-path IRGAs, QCL and LGR |
| Meteo input | none | the 6 meteo variables, in particular for temperature, pressure and relative humidity |
| Setup | may be rough | as exact as possible, e.g. separation between sonic and gas analyzer, sonic orientation |
| Additional output | not needed | e.g. random uncertainty and footprint |
| Output files | minimal | more, e.g. binned spectra |

## Before the L1 run

Needed for the L1 run:

- **Raw data** in ASCII format. The unzipped files from the OPENLAG run can be used again.
- **L0 OPENLAG results:** they show where the lag of each gas lies and whether the flux calculation worked. See [time lags](L0.md#time-lags-openlag).
- **The meteo input file** with the 6 screened meteo variables. See [meteo for EddyPro](Meteo_For_EddyPro.md).

Tips:

- **One folder:** collect the OPENLAG results, the meteo file, the `.eddypro` and the `.metadata` file in one folder.
- **Meaningful names:** e.g. `<SITE>_<YEAR>_[IRGA75]_R350-A_IRGA75-A.eddypro`: site, year, the gas analyzer the settings are for, then the instruments in the order of the columns in the raw data files (sonic first).
- **Same name:** the `.metadata` file has the same name as the `.eddypro` file.
- **Saving:** in the EddyPro interface, "Save" saves the `.eddypro` file only. The `.metadata` file is saved automatically.
- **Keep the files:** store the `.eddypro` and `.metadata` files of each run with the dataset.
- **Periods:** setups change over the years. Use one settings file per period with the same setup, e.g. two runs in a year in which the gas analyzer was replaced.

## Time lags

- **IRGA (CO2, H2O):** covariance maximization in a narrow window around the nominal lag. Without a clear covariance peak in the window, EddyPro uses the nominal lag.
- **QCL and LGR (N2O, CH4):** a constant lag, per year or per period in which the lag changed.
- **Window:** typically from 0 s to 5 s if the lag stays below 5 s, otherwise to 10 s. The minimum can be negative.
- **Where to set them:** nominal lag, minimum and maximum per gas in the raw file description (Metadata).

## Open-path IRGA

- **Closed-path IRGA** (e.g. LI-7200): the fluxes do not change after L1.
- **Open-path IRGA** (e.g. LI-7500): CO2 fluxes may need a correction for the self-heating of the sensor, after L1. It is not part of the chart.
- **Self-heating correction in EddyPro** (off-season uptake correction, Burba et al., 2008): not used. It was developed for vertically mounted instruments and does not account for an inclined IRGA, e.g. tilted by 15°. The self-heating effect of an inclined IRGA is assumed to be much smaller. In a comparison with parallel closed-path fluxes, the EddyPro correction performed poorly.
- **When it is needed:** the correction was developed for cold conditions, mainly below -10 °C.
- **Without parallel measurements:** applying the correction is risky, because its effect cannot be checked. With a closed-path IRGA next to the open-path one, the correction can be scaled to match it (Kittler et al., 2017).
- **Gap-filling:** gap-filling uncorrected open-path fluxes amplifies too high uptake.

## EddyPro settings

The settings of the L1 run, in the order of the EddyPro interface. Values in `<...>` are site-specific; "e.g." marks a common choice.

### Project creation

| Setting | Value |
|---|---|
| Project name | `<site>` |
| Raw file format | ASCII plain text |
| Metadata file | use alternative file: the `.metadata` file next to the `.eddypro` file. [fluxrun](scripts/fluxrun.md) finds it on its own, but selecting it here allows checking and editing it |
| Biomet data | use external file: the 6 meteo variables from [meteo for EddyPro](Meteo_For_EddyPro.md) |

### Metadata

**Site**

| Setting | Value |
|---|---|
| Altitude, latitude, longitude | `<site>` |
| Canopy height | `<m>`; a mean estimate if no measured canopy height is available |
| Displacement height | `<m>`; estimate: 0.67 × canopy height |
| Roughness length | `<m>`; estimate: 0.15 × canopy height |

- **Changing canopy height,** e.g. after a harvest: EddyPro can read a dynamic metadata file with the canopy height per period. It can also hold other changes, e.g. of the sonic height. The canopy height can be modelled from biomass samples or height measurements.

**Files**

| Setting | Value |
|---|---|
| Timestamp refers to | the time in the file name; for [bico](scripts/bico.md) files it is the start of the file |
| File duration | the length of a file, e.g. 360 min for six-hour [sonicread](scripts/sonicread.md) files, 30 min for 30-minute [rECord](scripts/rECord.md) files |
| Acquisition frequency | 20 Hz |
| Field separator | comma |
| Header rows | 3 for [bico](scripts/bico.md) files, 4 for [rECord](scripts/rECord.md) files |

- **Shorter files** are fine, as long as the time in the file name is correct. A file without enough data for a valid 30-minute flux gives no flux for that period.

**Instruments**

| Setting | Value |
|---|---|
| Anemometer | manufacturer and model; firmware version and instrument ID are optional |
| Height | `<m>` |
| Wind data format | U, V & W |
| North alignment | axis |
| North offset | `<°>`: the angle, clockwise from north, in which the north arrow of the sonic points, e.g. 20°. The [wind direction check](L0.md#wind-direction) in L0 helps to confirm it |
| Gas analyzers | manufacturer, model, instrument ID |
| Separation | northward, eastward and vertical separation from the sonic, in `<cm>` |
| Closed-path analyzers | also tube length, tube inner diameter, nominal flow rate, longitudinal and transversal path length, time response |

- **Separation:** EddyPro uses it to estimate the high-frequency losses from the distance between the instruments.
  - The first anemometer in the `.metadata` file is the centre of the coordinate system.
  - The axes point to true north, corrected for the local declination.
  - Positive if the gas analyzer is north, east or above the anemometer.
  - Open-path IRGA (LI-7500): between the sample volumes; vertical: between the midlines.
  - Closed-path IRGA (LI-7200): from the anemometer sample volume to the air inlet.

**Raw file description**

- **Order:** the columns in the same order as in the raw data files. If unsure, open a raw data file and compare.
- **Sonic:** e.g. u, v, w in m s-1, sonic temperature in K or °C, and inclinometer columns, which are normally not used.
- **Gas analyzer:** the gas columns with the correct units, e.g. molar densities of CO2 and H2O for an open-path LI-7500.
- **Time lags:** nominal lag, minimum and maximum for each gas. See [time lags](#time-lags).

### Basic settings

| Setting | Value |
|---|---|
| Files info | set by [fluxrun](scripts/fluxrun.md) |
| Missing samples allowance | e.g. 10 % |
| Flux averaging interval | 30 min |
| North reference | `<magnetic or geographic north>` |
| Master anemometer | `<sonic>`; if it does not show up, it is missing in the `.metadata` file |
| CO2 and H2O, open-path IRGA (LI-7500) | molar densities |
| CO2 and H2O, closed-path IRGA (LI-7200) | mixing ratios |
| N2O and CH4, QCL or LGR | mixing ratios |
| Cell measurements | closed-path analyzers: average cell temperature and cell pressure |
| Ambient measurements | from the biomet file: TA, PA, RH, SW_IN (listed as global radiation), LW_IN, PPFD |
| Diagnostics | e.g. the AGC of the IRGA, for the signal strength flag in [L2](L2.md) |

"Mixing ratio" is the same as "dry mole fraction".

### Processing options

| Setting | Value |
|---|---|
| Wind speed measurement offsets | 0 / 0 / 0 |
| Fix w boost bug | no; only for Gill WindMaster sonics |
| Angle-of-attack correction | no. It seems to overestimate CO2 uptake. Exception: an existing dataset that used it, to stay consistent |
| Axis rotation for tilt correction | double rotation (Wilczak et al., 2001) |
| Turbulent fluctuations | block average detrending |
| Time lag compensation | covariance maximization with default. See [time lags](#time-lags) |
| Density fluctuations (WPL) | yes for open-path IRGAs; no for closed-path analyzers that record mixing ratios. With their wet mole fractions instead, WPL is needed |
| Instrument sensible heat components (LI-7500) | no. See [open-path IRGA](#open-path-irga) |
| Quality check | Mauder and Foken (2004), 0-1-2 system. [L2](L2.md) adds more flags |
| Footprint estimation | Kljun et al. (2004) |

- **Planar fit:** an alternative to double rotation.
- **Kljun et al. (2015):** the newer footprint model is not in EddyPro, but scripts are available at [footprint.kljun.net](https://footprint.kljun.net/).

### Statistical analyses

| Setting | Value |
|---|---|
| Raw data tests | select all, with their default settings. [L2](L2.md) picks the flags it uses; other flags stay available, e.g. to filter a problematic period |
| Angle-of-attack limits | e.g. -35° to +35° instead of the default -30° to +30°, if the default removes too many records |
| Random uncertainty | Finkelstein and Sims (2001); integral turbulence scale: cross-correlation first crossing 1/e, maximum correlation period 10 s. It can also be estimated from the fluxes, outside EddyPro |

### Spectral corrections

| Setting | Value |
|---|---|
| Binned (co)spectra files | not available, so EddyPro calculates them |
| Tapering window | Hamming |
| Frequency bins | 50 |
| FFT | use power-of-two samples, which is faster |
| Lowest noise frequency | 1 Hz, all gases. For N2O and CH4, check the (co)spectra and adjust if needed |
| (Co)spectra QA/QC | default settings, e.g. minimum unstable, minimum stable and maximum: u* 0.2 / 0.05 / 5 m s-1, H 20 / 5 / 1000 W m-2, LE 20 / 3 / 1000 W m-2, CO2 2 / 0.5 / 100 µmol m-2 s-1, CH4 0.01 / 0.005 / 20 µmol m-2 s-1. For very low fluxes, e.g. N2O and CH4, set the limits lower |
| Minimum number of (co)spectra for valid averages | e.g. 10. A run over a whole year gives thousands |
| Filter (co)spectra by the raw data tests (Vickers and Mahrt, 1997) | no. The tests can be restrictive and remove too much data; with a year of data, the spectral model is smooth anyway |
| Filter (co)spectra by the quality check | remove low data quality (flag 2), keep moderate (flag 1) |
| Low frequency (high-pass filtering) | analytic correction (Moncrieff et al., 2004) |
| High frequency (low-pass filtering) | Horst (1997) for open-path IRGAs; Fratini et al. (2012) for closed-path IRGAs, QCL and LGR |
| Instrument separation | closed-path analyzers: yes, Horst and Lenschow (2009), crosswind and vertical only. Open-path IRGA: no, and make sure the box is empty even if it is greyed out |
| Spectral assessment file | not available, so EddyPro creates it |
| Assessment of high-frequency attenuation | default values, e.g. lowest frequency 0.005 Hz, highest 2 Hz. N2O and CH4 can need adjustments because of their low signal-to-noise ratio |
| Full w/Ts cospectra files | closed-path analyzers: not available |
| Include anemometer losses | yes; only with Fratini et al. (2012) |

- **Fallback to Moncrieff et al. (1997):** without enough (co)spectra, EddyPro uses Moncrieff et al. (1997), whatever method was selected, with no clear warning. The [fluxrun](scripts/fluxrun.md) log shows it. See [checks](#checks-after-the-l1-run).
- **Short periods:** a run over a few weeks rarely has enough (co)spectra. Use the spectral assessment file of a period with the same setup, close in time, e.g. the file of the previous year for January.
- **Several years:** a spectral assessment file from several years gives exactly the same correction in all years.

### Output files

| Setting | Value |
|---|---|
| Full output | yes |
| Fluxnet output | use the Fluxnet standard for biomet labels and units; error label `-9999` |
| Output format | output only available results |
| Build continuous dataset | yes. Missing periods are filled with the error code; this is not gap-filling |
| Biomet measurements, details of the steady state and turbulence tests, metadata | yes |

| Full-length cospectra | none. Full spectra and cospectra take much processing time and disk space |
| Processed raw data | statistics for all levels, no time series |

The fluxnet output file (30 min) goes on to the [flux post-processing chain](Flux_Post_Processing_Chain.md).

## Checks after the L1 run

1. **Output folder:** [fluxrun](scripts/fluxrun.md) created it.
2. **Data availability:** the plot shows no unexpected gaps.
3. **Flux files:** the `_fluxnet_` and `_full_output_` files exist. Only `.tmp` versions mean that the run failed.
4. **Spectral assessment file:** it exists. Without it, EddyPro fell back to Moncrieff et al. (1997), e.g. because the period was too short.
5. **Number of spectra:** the [fluxrun](scripts/fluxrun.md) log lists the binned spectra available for the spectral correction. It can be low for N2O and CH4.
6. **Spectral correction factor (SCF):** mostly between 1 and 2. Closed-path analyzers with an inlet have higher values than open-path IRGAs.
7. **Output:** fluxes, wind speed and direction, time lags, unexpected gaps.

When the SCF is too high, e.g. 2.5 to 5 for N2O or CH4, the spectral correction did not work:

- Check the ensemble (co)spectra in the spectral analysis output of EddyPro.
- Run periods with different instruments separately.
- Look for faulty instruments, e.g. a broken sonic distorts the cospectra.
- With too few records for unstable conditions, lower that threshold in EddyPro.

## Known issues

- **Empty SSITC flags in `_fluxnet_` files:** EddyPro before v7.0.7 wrote empty SSITC flags to the `_fluxnet_` file. It was fixed in EddyPro v7.0.7 and [fluxrun](scripts/fluxrun.md) v1.0. The `_full_output_` files are not affected; there the flags are called `qc_<flux>`. For older years, use the `_full_output_` files.
- **Check:** how many records each flag removes. The SSITC flag usually removes a lot, e.g. 25 %. A flag that removes 0 % stands out.

## Older fluxes

- **Settings change:** fluxes calculated years ago used older software and settings that are not necessarily the best today.
- **Metadata of old years** can be estimated, e.g. separations measured on old photos, or an uncertain sonic orientation.
- **Do not use fluxes blindly:** find out how they were calculated, and whether the older years should be reprocessed.
