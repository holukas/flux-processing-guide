---
title: "L3.2 · Outlier flagging"
---

Flags outliers in the fluxes. Management data can be used here, if relevant.

- **Flags only:** no data are removed in this step.
- **Input:** the storage-corrected fluxes from [L3.1](L3.1.md), filtered with the temporary QCF from [L2](L2.md). The tests only see data that passed L2.
- **One test after the other:** each test runs on the result of the previous one. Running all tests on the unfiltered data did not work well.
- **Repeat:** most tests run again until they find no more outliers.

## Tests

| Test | Flags |
|---|---|
| Absolute limits | values outside a physically plausible range |
| Manual flag | set periods, e.g. a known instrument failure |
| Hampel filter | values far from the median in a moving window, in multiples of the median absolute deviation; separate for day and night |
| Local standard deviation | values far from the rolling median, in standard deviations |
| Rolling z-score | values far from the rolling mean |
| Local outlier factor | records in a region of lower density than their neighbours; separate for day and night |

## Tips

- **Absolute limits:** look at the range of the highest-quality fluxes only. They scatter less and help to find sensible limits.
- **Day and night:** at many sites, flag outliers separately for daytime and nighttime, especially for NEE.
- **Nighttime uptake:** nighttime NEE sometimes shows unrealistic CO2 uptake. Left in, it affects the gap-filling. USTAR filtering removes most of it.
