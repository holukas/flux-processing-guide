L1 · Final flux run

Modified

29 September 2026

NoteSummary

The L1 run is the final fluxrun run once the year is complete, with the time lags from L0 and 6 screened meteo variables as input. Its EddyPro fluxnet output, 30 min, is the input for all later steps.

  • Boxes: 6 and 7 in the processing chain.
  • Input: the same raw data files as the L0 preliminary run.
  • Meteo input: 6 screened meteo variables, from meteo for EddyPro. See Biomet data.
  • Time lags: window size, nominal lags and constant lags from the L0 run.
  • Output: the EddyPro fluxnet output file, 30 min, with TIMESTAMP_END.
  • Runs on: a local installation, on demand.
  • Next step: flux post-processing chain.

L0 and L1 compared

The L1 run does not depend on the L0 run, but uses what L0 showed.

L0 L1
When during the year once the year is complete
Time lag compensation covariance maximization, no default covariance maximization with default
Time lag window as wide as needed as narrow as possible, e.g. 5 s for an open-path IRGA is not unusual
Spectral correction Moncrieff et al. (1997), faster Horst (1997) for open-path IRGAs; Fratini et al. (2012) for closed-path IRGAs, QCL and LGR
Meteo input none the 6 meteo variables, in particular for temperature, pressure and relative humidity
Setup may be rough as exact as possible, e.g. separation between sonic and gas analyzer, sonic orientation
Additional output not needed e.g. random uncertainty and footprint
Output files minimal more, e.g. binned spectra

Before the L1 run

Needed for the L1 run:

  • Raw data in ASCII format. The unzipped files from the OPENLAG run can be used again.
  • L0 OPENLAG results: they show where the lag of each gas lies and whether the flux calculation worked. See time lags.
  • The meteo input file with the 6 screened meteo variables. See meteo for EddyPro.

Tips:

  • One folder: the OPENLAG results, the meteo file, the .eddypro and the .metadata file are kept in one folder.
  • Meaningful names: e.g. <SITE>_<YEAR>_[IRGA75]_R350-A_IRGA75-A.eddypro: site, year, the gas analyzer the settings are for, then the instruments in the order of the columns in the raw data files (sonic first).
  • Same name: the .metadata file has the same name as the .eddypro file.
  • Saving: in the EddyPro interface, “Save” saves the .eddypro file only. The .metadata file is saved automatically.
  • Archive: the .eddypro and .metadata files of each run are stored with the dataset.
  • Periods: setups change over the years. One settings file is used per period with the same setup, e.g. two runs in a year in which the gas analyzer was replaced.

Time lags

  • IRGA (CO2, H2O): covariance maximization in a narrow window around the nominal lag. Without a clear covariance peak in the window, EddyPro uses the nominal lag.
  • QCL and LGR (N2O, CH4): a constant lag, per year or per period in which the lag changed.
  • Window: typically from 0 s to 5 s if the lag stays below 5 s, otherwise to 10 s. The minimum can be negative.
  • Setting location: nominal lag, minimum and maximum per gas in the raw file description (Metadata).

Open-path IRGA

  • Closed-path IRGA (e.g. LI-7200): the fluxes do not change after L1.
  • Open-path IRGA (e.g. LI-7500): CO2 fluxes may need a correction for the self-heating of the sensor, after L1. It is not part of the chart.
  • Self-heating correction in EddyPro (off-season uptake correction, Burba et al., 2008): not used. It was developed for vertically mounted instruments and does not account for an inclined IRGA, e.g. tilted by 15°. The self-heating effect of an inclined IRGA is assumed to be much smaller. In a comparison with parallel closed-path fluxes, the EddyPro correction performed poorly.
  • Conditions: the correction was developed for cold conditions, mainly below -10 °C.
  • Without parallel measurements: applying the correction is risky, because its effect cannot be checked. With a closed-path IRGA next to the open-path one, the correction can be scaled to match it (Kittler et al., 2017).
  • Gap-filling: gap-filling uncorrected open-path fluxes amplifies too high uptake.

Raw file description

  • Order: the columns in the same order as in the raw data files. If unsure, a raw data file shows the order.
  • Sonic: e.g. u, v, w in m s-1, sonic temperature in K or °C, and inclinometer columns, which are normally not used.
  • Gas analyzer: the gas columns with the correct units, e.g. molar densities of CO2 and H2O for an open-path LI-7500.
  • Time lags: nominal lag, minimum and maximum for each gas. See time lags.

  • Fallback to Moncrieff et al. (1997): without enough (co)spectra, EddyPro uses Moncrieff et al. (1997), whatever method was selected, with no clear warning. The fluxrun log shows it. See checks.
  • Short periods: a run over a few weeks rarely has enough (co)spectra. The spectral assessment file of a period with the same setup, close in time, can be used instead, e.g. the file of the previous year for January.
  • Several years: a spectral assessment file from several years gives exactly the same correction in all years.

Checks after the L1 run

  1. Output folder: fluxrun created it.
  2. Data availability: the plot shows no unexpected gaps.
  3. Flux files: the _fluxnet_ and _full_output_ files exist. Only .tmp versions mean that the run failed.
  4. Spectral assessment file: it exists. Without it, EddyPro fell back to Moncrieff et al. (1997), e.g. because the period was too short.
  5. Number of spectra: the fluxrun log lists the binned spectra available for the spectral correction. It can be low for N2O and CH4.
  6. Spectral correction factor (SCF): mostly between 1 and 2. Closed-path analyzers with an inlet have higher values than open-path IRGAs.
  7. Output: fluxes, wind speed and direction, time lags, unexpected gaps.

When the SCF is too high, e.g. 2.5 to 5 for N2O or CH4, the spectral correction did not work:

  • The ensemble (co)spectra in the spectral analysis output of EddyPro are checked.
  • Periods with different instruments are run separately.
  • Faulty instruments are a possible cause, e.g. a broken sonic distorts the cospectra.
  • With too few records for unstable conditions, that threshold is lowered in EddyPro.

Known issues

  • Empty SSITC flags in _fluxnet_ files: EddyPro before v7.0.7 wrote empty SSITC flags to the _fluxnet_ file. It was fixed in EddyPro v7.0.7 and fluxrun v1.0. The _full_output_ files are not affected; there the flags are called qc_<flux>. For older years, the _full_output_ files are used.
  • Flag check: how many records each flag removes. The SSITC flag usually removes a lot, e.g. 25 %. A flag that removes 0 % stands out.

Older fluxes

  • Settings change: fluxes calculated years ago used older software and settings that are not necessarily the best today.
  • Metadata of old years can be estimated, e.g. separations measured on old photos, or an uncertain sonic orientation.
  • Before reuse: how the fluxes were calculated is checked, and whether the older years should be reprocessed.
